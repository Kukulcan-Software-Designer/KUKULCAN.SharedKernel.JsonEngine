# Code Coverage

## Scope

Coverage targets the production `KUKULCAN.SharedKernel.JsonEngine` assembly.

Unit-test and integration-test assemblies, plus compiler-generated code, are excluded from the production coverage scope.

## CI Coverage Workflow

The coverage workflow runs:

- JsonEngine unit tests with Cobertura;
- JsonEngine integration tests with Cobertura;
- artifact publication for both suites.

Coverage is generated by `.github/workflows/coverage.yml`.

## Coverage Priorities

Coverage should be interpreted by behavior, with particular attention to:

- malformed and boundary JSON input;
- path resolution and typed access;
- condition evaluation;
- SQL clause parsing and execution;
- numeric versus string ordering;
- limit handling;
- graph rebuild and traversal;
- unknown graph nodes;
- PageRank parameters, empty graphs and dangling nodes;
- index lookup and tokenization;
- AI QUERY parsing and execution;
- natural-language translation boundaries;
- cancellation or resource-boundary behavior when introduced.

## Policy

The project follows:

```
TEST → RED → Source → GREEN → Coverage → PR → merge
```

Coverage is an audit signal, not the objective.

A new test must be justified by behavior, robustness, security or regression requirements. Tests must not be added solely to increase percentages.

## Interpreting Results

Coverage from unit tests demonstrates isolated deterministic behavior.

Coverage from integration tests demonstrates cross-component execution. Neither number alone establishes that every semantic contract is correct.

Coverage figures in documentation should only be updated from a current CI artifact or a locally reproduced coverage run.
